# 开发规范

## 元提示 (Meta-Prompt)

> **Agent执行开发的核心指南 - 必须严格遵守**
>
> ### 执行原则：
> 1. **先确认后修改** - 在修改任何代码前，必须核对任务是否来自已批准的需求文档（requestdoc.md / requestlist.md）
> 3. **按序完成任务** - 逐项完成标记为 `[ ] 待开发` 的任务，完成后立即改为 `[x] 已完成`
> 4. **每步可执行检验** - 每完成一个任务，代码必须能编译通过且功能可验证
> 5. **小步前进、避免返工** - 单个任务职责清晰、代码改动最小化、避免跨任务依赖过深
> 6. **保护已有功能** - 新需求加入时，仅修改相关模块，保护已实现功能的稳定性和向后兼容性
> 7. **规范的需求检查与代码验证** - 在确认需求、进行开发工作之前，必须进行全面的前置检查：包括验证当前代码是否可运行无错误、需求描述是否合理清晰、要进行的开发工作是否满足上述执行原则（特别是小步前进、模块化、避免跨任务依赖）。若发现任何问题应立即反馈而非盲目开发。
> 8. **新增任务的生成与确认** - 每一项新增到 `tasklist.md` 任务，均基于 `META_for_prompt`、`requestdoc` 和 `requestlist` 和`tasklist.md` 的内容，由软件架构专家经过深思熟虑动态生成。任务的制定遵循"小步前进"的原则，确保每次改动都围绕项目的框架核心，最小化更改范围，聚焦于最小可验证的 Demo。每一项开发任务都需先生成明确的 `tasklist` 描述，并在开发者确认后方可进行代码修改，以保证开发过程的可控性和高效性。**生成 tasklist 本身也必须遵循小步前进：每次只添加下一个最小的、可独立验证的任务，而非一次性列举所有任务。**

## 项目概况

**项目名**: VS Code Chat Extension - Strategy-based Prompt Enhancement
**核心需求** (来自 requestdoc.md):
- 实现一个Copilot Chat Participant (@strategy)
- 用LLM自动判定最优的Prompt增强策略（不做本地特征抽取）
- 支持6种策略：BASE, COT, TOT_SIMPLE, META, FEWSHOT, CHAIN
- 单次LLM调用完成策略选择和Prompt生成
- 交付：`strategyParticipant.ts` + 在 `extension.ts` 注册

**核心设计原则**:
- 全由LLM判定，无启发式算法
- 每一步开发完成后代码可执行
- 模块化设计，便于独立测试和扩展
